# Zero-meta deliverable — the file IS the deliverable

When rendering is mechanical (no filter, no rewrite between the source file and the final audience's screen), the file **is** the deliverable: only displayed content enters it. Banned, zero exceptions: intent/narration messages ("here we'll say…"), author-side inputs (what the reader is meant to take away, judgments about the audience), tempo/staging notes ("let it breathe", "cold open"), any cross-reference to another item ("see slide 7", "as seen this morning" — links are spoken, never written on screen), and **the state of your own knowledge base** (confidence levels, "to be confirmed", source ids): a fact not solid enough to be stated bare gets settled *upstream*, never exposed to the audience. Everything fabrication-related (specs of visuals to produce, intentions, must/nice priorities) lives in a **sidecar file** per section — anchored to items by locator, never rendered, hence invisible to the client. Test: if a sentence *describes what will be done or said* (or what is/isn't known), it's not content → out; if the final reader reads it on screen as-is, it stays. In doubt, out.
