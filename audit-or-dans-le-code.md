## A. Candidats forts — nouvelles entrées proposées

- **Purge de l'output au claim (guard anti-ancrage)** — au claim d'un reduce, le script `unlink()` l'ancienne version du fichier consolidé : l'agent est *mécaniquement* forcé de `Write` neuf au lieu d'`Edit` (qui exigerait un `Read` et l'ancrerait sur l'ancien texte au lieu de re-dériver des fragments). Purge sous flock mais non committée (crash → HEAD intact) ; `reopen` ne purge pas (la KB reste grepable pendant l'attente). Exemple pur de « guard par code contre un biais cognitif d'agent ». (`consolidation-pipeline/task.py:339-350`) **→ INDEX, nouvelle entrée §1.**
- **Purge de `CLAUDE_CODE_SESSION_ID` de l'env des workers** — chaque spawn `claude -p` reçoit l'env parent *moins* cette variable, sinon tous les workers héritent du session id de l'orchestrateur → même « short » partout → la garde auteur≠validateur du 2/2 devient inopérante. (`consolidation-pipeline/orchestrate.py:128,758,1091`) **→ INDEX (enrichit §1.4 ou §2.1).**
- **Identité du worker lue dans son propre JSONL** — conséquence du point précédent : l'orchestrateur ne connaît pas le short a priori ; il parse les ~50 premières lignes du stream-json (event `system/init`, champ `session_id`), tronque à 8. Unique source d'identité d'un agent mort → indexe force-release et comptage de commits. Best-effort (None → skip loggé, audit différé). (`consolidation-pipeline/orchestrate.py:202-231` ; `extraction-pipeline/orchestrate.py:514-547`) **→ INDEX.**
- **`stream-json --verbose` → fichier = un flux, quatre usages** — `--output-format stream-json --verbose`, stdout redirigé vers un fichier ouvert par le parent (jamais PIPE → pas de deadlock de buffer). Le même fichier sert : (a) sliding watchdog par mtime, (b) digest d'audit, (c) détection du session id, (d) forensique post-mortem. (`consolidation-pipeline/orchestrate.py:1092-1103`) **→ INDEX (enrichit §2.3).**
- **Verdict déterministe pré-calculé injecté dans l'audit sémantique** — l'orchestrateur calcule lui-même le dépassement de quota et injecte `PLAFOND: … → ⚠ DÉPASSEMENT|ok` dans le prompt d'audit, avec ordre « verdict kill sans débat, tu n'as rien à recompter ». Le quantifiable est tranché par du code, le modèle cheap ne juge que le qualitatif. Baseline du quota = la cellule non-releasée du board (le protocole claim/release fournit le point de départ gratuitement, zéro état orchestrateur). (`extraction-pipeline/orchestrate.py:430-458,249-262,408-427`) **→ INDEX (enrichit §2.3).**
- **Audit désarmé + non-bloquant + last-VERDICT-wins** — le subprocess d'audit part **sans `--allowedTools`** (tout est inline dans le prompt → il ne peut pas tenter un `Read` du log 5 Mo et timeouter), stdout direct en fichier, fd fermé côté parent ; un seul audit en vol, avec sa propre deadline (audit qui traîne → tué, verdict continue) ; parsing = la **dernière** ligne `VERDICT:` (le modèle délibère avant de conclure) ; toutes les branches d'erreur convergent vers continue. Clause anti-sur-kill dans le prompt : si la fin du log montre que l'agent s'est auto-corrigé → continue. (`consolidation-pipeline/orchestrate.py:743-787` ; `extraction-pipeline/orchestrate.py:587-653,237-291`) **→ INDEX (enrichit §2.3).**
- **Digest d'audit borné par construction** — compteurs globaux à coût constant (total events, `tool_use` par nom, erreurs) + tail des 50 derniers events, chaque champ tronqué à 400 chars, blobs base64 → `<image>` ; log illisible → chaîne dédiée, jamais d'exception. La taille du digest est invariante du contenu — sinon l'audit timeouterait précisément sur les agents longs, ceux qu'il surveille. (`consolidation-pipeline/orchestrate.py:610-715` ; `extraction-pipeline/orchestrate.py:294-398`) **→ INDEX (enrichit §2.3).**
- **Kill par process group entier** — workers et audits lancés `start_new_session=True` ; kill = `os.killpg(os.getpgid(pid), SIGKILL)` avec fallback `proc.kill()` idempotent, puis `wait()` pour moissonner. Un `claude -p` forke task.py/git/bash : tuer le seul claude fuit ses enfants (qui tiennent des verrous). (`consolidation-pipeline/orchestrate.py:894-934` ; `extraction-pipeline/orchestrate.py:477-488`) **→ INDEX (enrichit §2.3).**

## B. Candidats moyens — enrichissements ponctuels

- **Retry borné sur `.git/index.lock`** — retry **uniquement** si `"index.lock" in stderr`, backoff 0.05→0.4 s, toute autre erreur remonte, jamais de suppression du lock soi-même. Gère la collision avec des commits hors-flock (autre pipeline, même repo). (`consolidation-pipeline/_store.py:209-233`) **→ INDEX (§3.2).**
- **Commit no-op-safe scopé** — `git add -- <paths>` (nécessaire pour les untracked, que §3.2 rate) puis `git diff --cached --quiet -- <paths>` comme prédicat avant `commit -- <paths>` : l'appelant committe sans pré-vérifier. Pendant extraction : garde `git ls-files` avant le pathspec (sinon « pathspec did not match » sur dossier vide), et jamais de staging du slug_dir en force-abandon (extract avorté). (`consolidation-pipeline/_store.py:247-253` ; `extraction-pipeline/release.py:315-349`) **→ INDEX (§3.2).**
- **Comptage par agent : la commande exacte** — `git rev-list --count -F --grep=<short> <before_sha>..HEAD` : `-F` (le short est un littéral, pas une regex), fenêtrage par SHA capturé au spawn, fallback delta global si short introuvable. (`consolidation-pipeline/orchestrate.py:1035-1057`) **→ INDEX (§2.2).**
- **`task_id` de spawn = label, jamais une vérité** — l'orchestrateur peek pour choisir le *prompt de rôle*, mais l'agent claime lui-même et peut tenir une autre tâche (course entre slots) ; toute la récup est indexée `owner==short`. - **`owner` = sémaphore de passe de validation** — claim d'une passe : `owner=<short>` sans changer `status` ; 1er ok → owner **vidé** pour libérer la place du 2e valideur ; sélection exclut owner non vide.
